= DII MCPの概念とデータモデル
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ./media/


[role="lead"]
これらの概念を理解することで、AIアシスタントは適切なツールを選択し、有効なクエリを構築できるようになります。


NOTE: DII MCPはlink:concept_preview_features.html["プレビュー"]機能であるため、変更される可能性があります。



[[tenant-scope]]
== テナントの範囲

すべてのDII MCPリクエストは、認証されたユーザーのDIIテナントおよび権限の範囲内で実行されます。ツールは、そのテナント内に存在し、かつそのIDからアクセス可能なデータのみを返すことができます。



[[acquisition-units]]
== 取得ユニット

取得ユニット（AU）は、リモートにインストールされたエージェントであり、データソースをポーリングしてテレメトリをDIIに報告します。AUレコードには、接続ステータス、レポートの鮮度、オペレーティングシステム、バージョン、および割り当てられたデータソースの数が含まれます。

接続と報告は異なるシグナルです。たとえば、AUは、成功した報告履歴がなくても接続を受け入れることができます。ステータスと `lastReported`の両方を評価します。



[[data-sources]]
== データソース

データソース（コレクタとも呼ばれる）は、ストレージアレイ、スイッチ、ハイパーバイザー、またはクラウド サービスなどのインフラストラクチャシステムへの構成済み接続です。

インベントリやステータスを確認するには、リスト操作を使用します。収集パッケージ、ポーリング間隔、最近のアクティビティなどの構成の詳細が必要な場合は、特定のデータソースを取得します。

サポートされているデータソースの種類は、より広範なDIIコレクターカタログを説明しています。これらは、現在のテナントで設定されているコレクターとは異なります。



[[objects]]
== オブジェクト

オブジェクトとは、ストレージシステム、プール、ボリューム、ホスト、仮想マシン、Kubernetesワークロード、製品固有のリソースなど、正規化されたインフラストラクチャエンティティのことです。

オブジェクトの種類は動的です。常に：

. オブジェクトの種類を一覧表示します。
. 正確な種類を選択してください。
. その型のメタデータを取得します。
. メタデータで宣言されている属性とメトリックのみをクエリします。




[[attributes-and-metrics]]
=== 属性と指標

* *属性*は、識別情報、構成、所有権、ラベル、または関係性を記述します。
* *メトリクス*とは、容量、遅延、スループット、利用率など、時間とともに変化する測定値のことです。
* グループ化可能な属性を使用すると、集計クエリを分割できます。


メトリックフィルタは、要求された時間枠集計が適用される前に、生のメトリック値に対して評価されます。



[[logs]]
== Logs

ログタイプは、ONTAP EMS、Kubernetesイベント、StorageGRIDイベント、VMwareイベント、およびDIIプラットフォームイベントなどのイベントストリームを表します。

ログクエリもメタデータ優先です：

. 利用可能なログの種類を一覧表示します。
. 選択したタイプのメタデータを取得します。
. 有効な属性のみを要求してください。
. イベントを検索したり、イベント数のヒストグラムを作成したりできます。




[[monitors-and-alerts]]
== 監視とアラート

モニターは、DIIが評価する条件を定義します。アラートとは、1つまたは複数の関連オブジェクトに関する特定のモニター結果のことです。

* 監視ツールを使用して、意図、ステータス、オブジェクトの種類、および修正ガイダンスを確認します。
* アラートを照会する前に、アラートメタデータを使用してください。
* 1つのアラートを取得するには、 `AL-123456`などのアラート名またはそのUUIDを使用します。


アラートのステータスと重大度は別々の次元です。結果の優先順位を決定する際は、両方を要求してください。



[[maintenance-windows]]
== メンテナンス時間帯

メンテナンスウィンドウは、定義された期間中に式に一致するアラートを抑制します。成功した結果が空であることは、一致するウィンドウが存在しないことを意味します。これはデータが欠落している証拠ではありません。



[[notification-rules-and-targets]]
== 通知ルールと対象

通知ルールは、一致するアラートをルーティングします。ターゲットには、Slack、Microsoft Teams、PagerDuty、またはカスタムHTTP統合を含めることができます。

Webhookアドレスには機密情報が含まれている可能性があります。レポート作成時には、対象名、エンジンタイプ、およびステータスのみを要求してください。アドレス全体を絶対に再現しないでください。



[[metadata-first-query-flow]]
== メタデータ優先のクエリフロー

[source, text]
----
Discover types
    → retrieve type metadata
        → select valid attributes and metrics
            → query a bounded time range
                → paginate, group, or retrieve time series
----


[[filters]]
== フィルタ

DIIクエリツールは、条件とネストされた論理演算子をサポートしています：

* 比較： `EQ`、 `NE`、 `GT`、 `LT`、 `GE`、 `LE`
* パターンマッチング： `WILDCARD`
* プレゼンス： `EXISTS`
* 論理： `and`、 `or`、 `not`


メタデータで宣言されているフィールド名と互換性のある値型を正確に使用してください。 `EXISTS` の場合、接続先のサーバーバージョンでサポートされていれば、比較値を省略します。



[[time-ranges-and-pagination]]
== 時間範囲とページネーション

* ISO-8601タイムスタンプを明示的なオフセットとともに使用するか、 `Z`。
* 必要に応じて、+America/New_York+ や `UTC`などのIANAタイムゾーンを指定してください。
* ツールにそれよりも短い期間が明記されていない限り、クエリの期間は30日以内にしてください。
* オブジェクトクエリとアラートクエリは一般的に `limit`と `offset`を使用します。
* ログイベントクエリは、次のページ用に返されたカーソルを使用します。


エラーと復旧手順については、link:mcp_troubleshooting.html["トラブルシューティング"]を参照してください。
